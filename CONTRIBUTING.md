# Contributing

Thanks for helping maintain this WordPress plugin portfolio.

## Start with the outcome

Describe the observable behavior, compatibility expectations, and acceptance
criteria before beginning a substantial change. Security reports belong in the
private reporting channel described in `SECURITY.md`.

## Pull requests

- Keep each pull request focused and reversible.
- Add regression coverage for behavior changes and bug fixes.
- State the PHP, WordPress, multisite, and integration combinations tested.
- Identify database changes, destructive behavior, new dependencies, new
  network access, and release-process changes.
- Do not commit credentials, build caches, development databases, or generated
  release ZIP files.
- Wait for every required check and resolve review conversations before merge.

AI-assisted contributions are welcome, but the pull request author remains
responsible for understanding and validating the result. AI-generated changes
do not receive reduced review merely because the checks are green.

By contributing, you agree that your contribution uses the license declared by
the target repository.
